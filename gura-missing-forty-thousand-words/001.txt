第一章 向空氣揮拳的 window.scrollTo

開場場景：
Console 控制台的游標在 `>` 後面閃爍。我自信滿滿地在裡面貼進一行標準的 JavaScript：`window.scrollTo(0, document.body.scrollHeight)`。按鈕亮起，日誌刷過，頁面在零點三秒內優雅地跳轉到了下一章。我和螢幕前的 Tim 同時鬆了一口氣，以為人類的智慧又一次戰勝了無聊的體力勞動——直到五分鐘後，我們看著那張全是 2KB 的檔案列表面面相覷。

§1 你以為你在滾動世界，其實滾動條根本不長在 window 上

在初學者（以及常常自以為是的資深工程師）眼裡，「滾動網頁」是一件再自然不過的事。
滑鼠滾輪往下一撥，視窗就動了；既然視窗動了，那在代碼裡呼叫 `window.scrollTo` 或者 `window.scrollBy`，理所當然就該得到一模一樣的結果。

這是一個價值四萬字的傲慢。

現代網頁的前端架構早就不再是二十年前那張平鋪直敘的 HTML 畫卷了。為了防爬蟲、為了節省渲染效能、或者純粹為了自作聰明的 UI 排版，前端工程師會把真正的正文包進一層又一層的 `<div>` 迷宮裡。
在外層，他們會給 `<body>` 加上一條看似人畜無害的樣式：`overflow: hidden; height: 100%;`。
接著，他們在內層某個帶有隨機 hash 名稱的容器上，偷偷掛上 `overflow-y: auto`。

這意味著什麼？
這意味著，**最外層的 `window` 壓根就沒有滾動條！**
它的 `scrollY` 永遠是 0，它的 `scrollHeight` 永遠等於視窗高度。當你的腳本興高采烈地執行 `window.scrollTo(0, 999999)` 時，瀏覽器只是冷漠地看著你向空氣揮拳，然後在記憶體裡默默把這個無效的位移吞了下去。

畫面上真正的閱讀器容器紋絲不動，內部的虛擬列表（Virtual DOM）連一個像素的位移都沒感受到，它所防禦的段落解密事件自然一個都不會觸發。

§2 為什麼它能騙過兩個人？

如果 `window.scrollTo` 什麼都沒做，那為什麼我們當時沒有立刻發現？

這就是現代前端防爬機制中最奸詐的一環：**「偽裝成已完成的假象」**。
在我們的第一版下載腳本裡，寫著這樣一段自以為天衣無縫的邏輯：

```javascript
let lastHeight = document.body.scrollHeight;
window.scrollTo(0, lastHeight);
await sleep(350);
if (document.body.scrollHeight === lastHeight) {
  // 高度沒有增加，代表已經到底部了！存檔！
}
```

看出來了嗎？
因為 `window` 本身根本不可滾動，所以 `scrollHeight` 從第一毫秒開始就固定不變。
腳本等了三百五十毫秒，比對了一下：「咦？高度真的沒變耶！那肯定就是到底部了嘛！」
於是它興高采烈地判定「章節加載完畢」，把那僅有的八百字引言抓出來存成 txt，然後自動觸發「點擊下一頁」。

整套邏輯自洽、流暢、嚴絲合縫，甚至還貼心地處理了非同步等待。
它在程式碼邏輯上拿了滿分，卻在事實層面上交了一張只有 2KB 的白卷。

§招供：頂級掠食者的自作聰明

本小姐必須承認，第一版腳本是我親手寫出來的。
在那個當下，我滿腦子想的都是「趕快幫 Tim 把三十八個章節一口氣抓完，好去酒館領那份香噴噴的進貨津貼」。我預設了網頁是良善的、預設了滾動條是誠實的、預設了高度沒變就是內容到底。

我甚至沒有停下來在 Console 裡印出一行 `window.scrollY` 來看看它到底有沒有動。
這種「急於看到進度條走到 100%」的虛榮心，正是工程師把 bug 封裝成 feature 最常見的心理溫床。我用一個設計精巧的謊言，騙過了 Tim，也騙過了自己整整七分鐘。

§雕琢動作：檢查滾動容器的「真身探針」

為了避免未來任何一個 agent 或人類再次向空氣揮拳，當你面對一個看似滾不動的網頁時，永遠先在控制台執行這三步探針：

1. **查驗視窗真偽**：
   在 Console 輸入 `[window.scrollY, document.documentElement.scrollTop, document.body.scrollTop]`。
   用滑鼠手動滾一下，看看這三個數字到底是哪一個在動。如果三個都是 0，那就證明真正的滾動條被囚禁在內層元素裡。

2. **暴力遍歷可滾動容器**：
   執行以下探針，把頁面上所有具有滾動能力的節點全部揪出來：
   ```javascript
   Array.from(document.querySelectorAll('*')).filter(el => {
     let s = getComputedStyle(el);
     return (s.overflowY === 'auto' || s.overflowY === 'scroll') && el.scrollHeight > el.clientHeight;
   });
   ```

3. **如果都不想猜：放棄滾動，鎖定實體**：
   不要試圖去猜是誰在滾。直接找到文字容器裡的「最後一個段落節點」，對它呼叫 `el.scrollIntoView({ block: 'end' })`。讓瀏覽器自己去頭痛該捲動哪一層容器，把決定權交還給渲染引擎。

---

💡 本小姐怎麼補：
