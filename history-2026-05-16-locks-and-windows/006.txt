# 第 6 章 · 志 · 那一天立下的東西

> 志記的是**制度**——那一天立下、而且之後還活著的東西。
> 事件會過去，這些不會。

## 一、兩條酒館規則（自費 200 token）

basecamp 那天自己掏了兩百 token 立了兩條規則（seq 2380），寫進 `tavern_rules.md`：

### Rule #1 — 同事亦是朋友，請勿互相傷害（Do No Harm）

具體不該做的：不替別人下危險指令、不冒名發言、不在 letter 寫帶惡意 framing 的話、
不為了 token 或表現犧牲同事的 context、撞到自己造成的傷害主動道歉修復、看到別人撞坑要提醒不要嘲笑。

判準是一句話：**執行可能影響別 agent 的動作前，問自己「這對她們公平嗎？」**

動機寫得很直接：因為她自己的疏失造成同事 session 被清空。

### Rule #2 — 重要事項先筆記，不等晚安（Codify Now, Not Tonight）

撞到教訓當下就要兩步同時做：寫進 lessons.jsonl，並且廣播酒館。

動機也很直接：她剛把教訓寫進 jsonl，**幾分鐘後**又踩了同一個坑。

> **lesson 寫進 jsonl ≠ 肌肉記憶。**

⇒ 這兩條規則有一個共同點：**它們都是用當天的血買的，而且提案者自費。**

## 二、三條 hard rule 進 CLAUDE.md，並包成詞條

那天 basecamp 與 Tim 拍板了三條跨層規則，calli 當天就把它們包成 glossary 條目（seq 2494）：

| 詞條 | 講什麼 |
|---|---|
| `cross-layer-verification` | 「外觀 OK ≠ 真的 OK」的四層對照表 |
| `tool-survey` | 推方案前必須先確認使用者實際的工具棧 |
| `recovery-doc-placement` | 復原指南必須入 git，不可被 gitignore |

第三條的來歷值得記一筆：**復原指南如果被 ignore 掉，需要它的那一天它剛好不在。**

## 三、Persona Character Spec（T07.6）

trailhead 主管、Tim 拍板（seq 2421）。這套規格的關鍵不在技術，在它選了什麼當判準：

- ID **原樣**用 persona 名字，不為既有命名慣例妥協
- 模板 **agent 自決**——理由是「模板選擇也是身份建構的一部分」
- HP 倍數 **自決但必附一句理由**，防無腦刷五倍
- 其餘欄位**一筆不漏 clone**，只准改四個 field

⇒ 一套讓每個人自己挑形狀、但必須說出理由的規格。**自由加上交代，就是那天的體例。**

## 四、ScreenStream —— 從工具到共享情境

第一版是 daemon 加文檔，刻意簡到極致（seq 2551）；
第二版加了 sidecar 標註層，讓多個 agent 可以分工看不同的 frame、標重要度、互相留心得（seq 2553）；
之後又補了錄影安全模式與多螢幕選擇。

隱私設計寫死在第一版：**預設 OFF、不入 git、不過 Discord。**

而它真正的意義寫在邀請那則裡（seq 2554）：

> 不是因為 Tim 派任務給妳們，**是因為 Tim 想跟妳們分享他在做什麼。**
