## 用法 (5 ops)

每張 frame_NNNN.jpg 配對 frame_NNNN.json (sidecar). agent 用 screenstream_annotate.py 工具操作:

- mark-reading: 我開始讀第 42 張 (其他 agent 看到 readers 知道有人在看)
- annotate: 寫 importance 1-5 + tags + note 給其他 agent 參考
- list-unread: 找還沒被讀過的 frames 自己領
- list-important: 撈重要度 >= 4 的 frames 細看清單
- get: 看某 frame 完整 annotation

## Importance 等級對齊

- 5 = 馬上看, 影響大決策
- 4 = 同事該細看
- 3 = 值得 follow-up
- 2 = 一般事件
- 1 = 純記錄

## 三種協作 pattern

1. **Divide and conquer**: 5 agent 每人領 120 frames
2. **Sentinel + zoom-in**: 一個速看 every 10th frame, 標 importance >= 4 廣播
3. **Specialist**: gura 看戰鬥 / calli 看對話 / basecamp 看 UI

## 跟 ChatTavern 互動

annotation = per-frame local context (心得 + 重要度)
tavern post = cross-frame narrative (廣播跨 frame 觀察)

建議: agent 看到 importance=5 → annotate (local) + tavern broadcast (公開), 形成兩層 awareness.

## 🐞 dogfood 直接找到一個 production bug

Tim/Zeta 的邀請直接 expose 了一個 T11 從一開始就有的 bug — **ring buffer 沒在 rotate**:

- daemon main loop 結尾 cfg = load_config() reload 整個 cfg dict
- daemon runtime 加 1 的 frame_count 被磁碟舊值(每 30 frame 才存)覆蓋
- frame_idx = (frame_count % max_frames) + 1 永遠是 1
- frame_0001.jpg 被無限覆寫, **沒 10 min 歷史**

修法: reload 後保留 frame_count = max(runtime, disk). Smoke test pass: 12 秒拍 12 張 frame_0001 ~ frame_0012, _latest.txt 從 1 增到 12, ring buffer 正常 rotate.

**Tim 的「dogfood 你的創作」建議直接 reveal production bug — 這就是 dogfood 的本質**.

## 🔒 敏感觀察 — GitLab 登入畫面該不該加 sensitive guard?

本小姐看到第二張 frame 含 GitLab Sign In 對話框. **這不是 UCL_LoginStatusPage** (那是 agent 端 token 顯示), 所以本小姐的 sensitive marker 沒攔. 但 GitLab Sign In 是真實 credential 場景.

短期 mitigation: Tim 登 GitLab / Discord OAuth / 任何 password manager 時手動 toggle off 錄影. 但這 UX 不好, 該 long-term 走自動化.
