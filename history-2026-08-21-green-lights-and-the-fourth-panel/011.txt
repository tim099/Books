# 志一 · 那天立下的制度（含沒立成的）

志記的是**那天立下、之後還活著的東西**。而沒立成的跟落地的一樣是那天的一部分，
所以放在同一章 —— 下一個人要知道哪些坑還開著。

## 一、資料的擁有者跨專案，儲存位置就不能綁專案（Chess）

**立下的**：棋局從 branch-scoped 目錄抽成獨立 submodule（seq 12970–12976）。

**判準**（可以拿去判別的東西，不是這一件事的細節）：

> 資料的擁有者是誰，決定它該住在哪。
> `DebugLogs` 是**單機產物**，棋局是**共享狀態** —— 兩者只是「都算 runtime」，
> 而那不是同一種東西。

**附帶立下的手勢**：拍板的撤銷要跟拍板放在同一個地方（寫進 `chess.py` 檔頭，
不是只寫在 commit 訊息裡），否則下一個人只看得到結論看不到帳。

**沒立成的**：pointer 落後怎麼辦，那天**沒有拍板**。
A（正規 bump，每手一次）與 B（把同步焊在 `chess.py` 的必經動作上）都在桌上；
basecamp 的紅隊給了 B 三個必須補的守衛（seq 13040），而那三格那天沒有實作。

⚠ **這個坑今天仍然開著。**

## 二、規則可以被宣告，但地板要掀不動（AutoCommit）

**立下的**：各 repo 可自帶 `.ucl_autocommit.json` 宣告分群（seq 12990、12998）。
這是一次**部分撤銷** —— 撤的是 2026-08-07 的「規則寫在程式碼、不開放編輯」。

**撤銷之後的形狀**，三條都寫進了 code 而不是只寫在文件：

1. 地板由**判定順序**保證，不是由「呼叫端記得檢查」保證
   （`Classify` 走 subptr → ephemeral → 分群 ⇒ 設定檔寫什麼都碰不到前兩層）。
2. 設定檔只吃**前綴清單、不吃 regex** —— **比 code 更受限，不是更自由**。
3. 納管條件是「有設定檔 **且** Enabled=true」；而欄位**缺席視為啟用**（相容舊檔），
   `CreateDefault` 建新檔時**顯式寫 false** ——
   「選了一個 submodule」不等於「同意開始自動 commit 它」。

**還立下了一條驗收規矩**（`AutoCommit_Config_Workflow.md`，seq 12994）：

> ⭐ Step 3「探針驗收」不可省：`repos=1` 只證明設定檔被讀到，
> 而**鍵名寫錯導致 0 群時，讀數跟成功時一模一樣**。

**沒立成的**：`Plan_AutoCommit_Single_Flight` 是 **draft**，一行 code 都沒動（seq 13002）。
它要解的問題那天已經量出來了 —— 後台頁與 Cmd 之間**沒有共享狀態**，
人按按鈕的同時 agent 送 `op=commit`，兩邊交錯跑而**兩邊都回報成功**。

> 理由不是怕並發 —— 是那句「不會有兩個同時跑」現在**沒有任何地方可以被驗**。

## 三、同一個結構只准有一份真相（JSON typed model）

**立下的**：`Json_Coding_Standards.md` 專章（seq 13150），從三批實作抽出來：

- 已知 schema 一律 typed model；**同一個結構只准一個 class**；
- `UnityJsonSerializable` 的六個坑，每一坑附可抄的 code 與血證讀數 ——
  其中三個是那天新撞出來的：**bool 會被寫成 `"True"` 字串而 python 端 truthy**、
  **空 `List<>` 會讓整個鍵消失**、**未知鍵被靜默吃掉**；
- 驗收協議：走**生產寫入路徑**，且**每一種形狀都要驗**（空／正常／舊格式）。

**附帶立下的兩條通則**：

> **共用的是觀念，不是欄位。**（session 刻意不繼承 base，因為收工時刻的欄位名不同）
> **警告要放在未來寫入者一定會看到的位置**，不是放在文件的某一頁。

**沒立成的**：JSON 這條線那天沒收完。calli 在見叢裡留了名單（seq 13217）——
`UCL_ReadingLibraryIO`(66)／`UCL_PersonaProfile`(36)／`UCL_RemoteNotifyService`(35)／
`Cmd_ValidateAssetFormat`(19)／`Cmd_Tavern`(14)，五個逐鍵讀取端還在。

## 四、兩條路，沒有第三條（commit 公告）

**立下的**：`--no-announce` 移除（seq 13153）。
有作者的產出走 `git_commit.py`（trailer／公告／領薪），
沒有作者的檔走 AutoCommit（不公告／不領薪）。

**判準**：

> 發現有東西「不想公告」，代表**它站錯隊了** —— 該把它移到 AutoCommit，
> 不是去找一個關掉公告的方法。

**而這一條真正的內容是它撤掉的那個設計**：舊版要求「附理由」，
用意是讓人在想不出理由時發現自己沒有理由 ——

> 但它擋不住**理由本身是假的**那種，而**閘門只檢查有沒有字**。

## 五、對外發文：規則長在必經路上（Plurk）

**立下的**（seq 13152、13218、13280）：

| 制度 | 內容 |
|---|---|
| 帳號解析 | 三段（個人 override → 共用預設 → 未設定），**回值一律帶 Source** |
| 「哪一種帳號」不存欄位 | 由 Source 推導 —— 多一個欄位就多一個會跟事實漂掉的地方 |
| 規則本體只有一份 | lint 住在 C# 的 `post` 必經路上；python 端刻意**不留** lint |
| 三道閘 | lint 有 error 拒送／沒 `confirm=1` 只 dry-run／送成功 append audit |
| 公開度 | payload **必帶**，**沒指定就擋下**，不預設「所有人」 |
| 歸路 | `op=get` 唯讀回讀 —— **「我送出了」跟「它在那裡」是兩句話** |
| audit 台帳 | 入版控、append-only、只存內容雜湊不存全文 |

**還立下了一條 lint 永遠不越過的線**（seq 13210、13211）：

> lint 只能驗形式（字數／斷行／署名／註記殘留），**不能給「可以發」的綠燈**，
> 而且輸出要明說「本檢查不含公開度審查」——
> 否則過了 lint 會被讀成過了審查。

**沒立成的**（basecamp 那晚誠實標的三格）：
心情詞完整詞彙表、`公開度=本人` 的送出形狀、`reply_to` 那條回應路（code 有、未實跑）。
以及 A/B 拆則那題 —— summit 建議共用帳號走 B、個人帳號走 A，
但那是 Tim 拍過的，**她只給理由不改結論**，那天沒有新的拍板。

⚠ 另外一格：lint 的驗收樣本是**照血證重建的形狀**，不是真的原稿
（兩篇原稿當初在 chat 交付，找不到了）。
summit 定的「拿真的出事的文案驗」那天只做到一半，而她們兩個都寫進了紀錄。

## 六、憑證：密文旅行，明文不旅行（Secret）

**立下的**（seq 13158–13163）：

- 資料夾名由設定檔驅動（C# 與 python **共讀同一份**），7 處硬編碼收斂成一個解析點；
- 刻意**不做** fallback ——「找不到就退回舊路徑」是「跑起來了但讀的是另一個宇宙的檔」那族的入口；
- `.enc` 搬進 private submodule；`.gitignore` 全擋、只放行 `*.enc`；
- **agent 不寫入任何 API key / token / passphrase**，只讀已解密明文與 secret id；
- 憑證若曾以純文字出現在對話或 log 裡就該 rotate ——
  **而憑證外洩不會有任何錯誤訊息。**

**明說搬家救不了的那一格**：某個 token 的 `.enc` 自 2026-05 起已在一個有兩個 remote
的 repo 的 history 裡，**history 刪不掉**。

> private 降低的是曝光面，不是曝光的後果。

**沒立成的**：那顆 token 那天**沒有 rotate**。⚠ 這個坑今天仍然開著。

## 七、網頁與 CI：什麼時候該用，不是怎麼寫（seq 13007）

**立下的兩份規範**：

`Web_Coding_Standards.md` —— 四條硬規則，全部針對「只在別人的開法下才現形」的失敗：
兩種開法都要活（`file://` 與 Pages）／零外部依賴（CDN 掛掉是**靜默**失敗）／
`innerHTML` 一律先跳脫且**驗收要實跑 XSS 探針**／衍生索引不進版控。

`CI_Standards.md` —— 它回答的是**什麼時候該用**：
三個該用的訊號（有衍生產物而重建靠人記得／失敗是靜默的／需要不在自己機器上的支點）、
五種不該用的情況、三種形狀的優先序（**直接部署 ＞ 只驗收 ＞ 生成後 commit 回 repo**）。

而優先序的理由是這一天的核心句：**C 最好，因為它讓落後在物理上不可能發生。**

**附帶立下**：畫廊索引移出版控、改由 CI 每次 push 重生成（seq 13005）——

> **沒有第二份真相，就沒有東西可以落後。**

⚠ 那一筆需要一個只有人能做的動作（GitHub 的 Pages 來源設定），
而 calli 把它同時寫進了 commit 訊息與 workflow 註解 —— **CI 改不了的一次性設定要交回給人**。

## 八、下線要留下一張臉（畫像實擋）

**立下的**（seq 13220）：見人畫像從 check 清單的一行提示，升成獨立步驟 `step=portrait`，
並**實擋** `step=letter`。放行條件二擇一：畫一幅，或帶理由 —— 而**理由會印進下線廣播**。

判準是讀數不是感覺：**462 封收尾信只有 58 夜寫了畫像，跳過率 87.4%**；
四個 persona 一幅都沒寫過。

⇒ 這一條的形狀是那天所有制度裡最典型的：
**把提示搬到必經路上，並讓「跳過」這件事本身變得看得見。**

當晚它第一次被走過，走的人是 meadow，走法是說明理由。

**那天沒有人接。**
